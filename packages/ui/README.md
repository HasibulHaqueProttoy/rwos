# @rwos/ui

The Rocket Wave design system in code: design tokens, the Tailwind theme, shared components and the logo. Used by both apps.

## Using it in an app

`app/globals.css`:

```css
@import 'tailwindcss';
@import '@rwos/ui/styles.css';
```

Then import components from `@rwos/ui` and put one `<Toaster />` in the root layout.

To see every component in both themes, run `pnpm dev` and open http://localhost:3001/design-system (development only; it returns 404 in production).

## Tokens

| File | What it is |
| --- | --- |
| `tokens/rocketwave.tokens.json` | Exact copy of the design system tokens (Rocket Wave Design System artifact). Do not edit here; change the design system, then copy it again |
| `tokens/overrides.json` | Accessibility fixes to that file, each with the original value and the reason |
| `tokens/product.json` | Values from the design system README that are not in its tokens file (tap target, sidebar width, content width, logo colours, loaded font names) |
| `src/styles/tokens.css`, `src/styles/theme.css`, `src/components/logo-paths.ts` | Generated by `pnpm --filter @rwos/ui tokens:build`. Never edit by hand; a test fails if they are out of date |

The Tailwind theme contains **only** these tokens: the default palette, spacing scale, type scale, radii and shadows are removed. So `bg-surface`, `text-ink-muted`, `p-4`, `rounded-lg`, `text-h1` work, and `bg-red-500`, `p-7` or `text-sm` do not exist.

| Kind | Utilities |
| --- | --- |
| Colour | `bg-*`, `text-*`, `border-*` with: brand, brand-strong, brand-tint, flame, ink, ink-muted, ink-subtle, on-ink, on-brand, canvas, surface, surface-sunken, surface-hover, border, border-strong, focus, success(-tint), warning(-tint), danger(-tint), info(-tint), neutral-tint |
| Type | `text-display`, `text-h1`, `text-h2` (add `font-display`), `text-h3`, `text-body-lg`, `text-body`, `text-body-strong`, `text-label`, `text-caption`, `text-overline` (add `uppercase`), `text-data` (add `font-mono`) |
| Spacing | `0, 1, 2, 3, 4, 5, 6, 8, 12` (4 to 48px), plus `tap` (44px), `sidebar` (248px), `logo-min` (120px) |
| Width | `max-w-content` (1200px), `max-w-dialog`, `max-w-sheet` |
| Radius | `rounded-sm` (badges), `rounded-md` (inputs), `rounded-lg` (cards, dialogs), `rounded-full` (buttons) |
| Shadow | `shadow-sm` (cards, light theme only), `shadow-lg` (dialogs) |
| Focus | `focus-visible:focus-ring` (2px ring, 2px offset) |

Themes switch through the variables, so components never use `dark:`. The system setting decides by default; `data-theme="light"` or `"dark"` on `<html>` forces one.

## Components

Button (primary, secondary, ghost, brand, destructive), Input, Label, Select, Badge, Card, Dialog, Sheet, Table, Tabs, Toaster and `toast`, Logo. They follow shadcn/ui's structure (Radix primitives, `cva` variants, `cn()` for class merging), themed only from tokens.

Rules built into them: buttons are 44px tap targets and never submit a form by accident; badges require their status word; inputs are 16px on mobile; dialogs and sheets trap focus, close on Escape and have a labelled close button; tables use tabular numbers; the logo is full colour in the light theme and all white in the dark theme.

## Tests

`pnpm --filter @rwos/ui test` checks:

- WCAG 2.2 AA contrast for every text, border and focus colour pair, in both themes
- generated files match the token sources
- accessibility (axe) and behaviour of each component (keyboard, focus, Escape)
- no raw colours, arbitrary sizes, default-palette classes, `dark:` overrides, exclamation marks or em-dashes in UI source
- every Tailwind class used in the UI actually exists in the theme (Tailwind otherwise ignores a typo silently)

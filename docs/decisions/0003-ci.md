# 0003: Continuous integration and scanning

Date: 2026-11-08 · Status: accepted

## Decisions

- **GitHub Actions**, one workflow (`.github/workflows/ci.yml`) with four jobs: checks (lint, typecheck, test, build, format), migrations on a fresh Postgres 16, dependency audit, secret scan. Runs on every pull request and every push to `main`.
- **Free tools instead of GitHub's paid security features.** The repository is private, where GitHub's dependency review and secret scanning need a paid Advanced Security plan. Instead: `pnpm audit --audit-level high` (fails on high or critical advisories) and Gitleaks (open source, run from its Docker image, so no licence key is needed). Dependabot version updates are free on private repositories and are on for npm, GitHub Actions and the Docker Compose images.
- **Supply-chain hardening:** every action is pinned to a full commit SHA with the version in a comment; the Gitleaks image is pinned by digest; the workflow token is read-only (`permissions: contents: read`); checkout does not keep credentials.
- **False positives** are ignored one by one by fingerprint in `.gitleaksignore`, each with a reason, never by turning off a rule or a whole file.
- **Migration job is in place before migrations exist.** It uses `pnpm run --if-present`, so it passes cleanly now and becomes a real check when task 1.4 adds `db:migrate` and `db:seed`, with no workflow change.

## Why

The two-person team needs every pull request checked the same way, with no cost and no keys, and SECURITY.md requires dependency and secret scanning with no merge on high-severity findings.

## Revisit when

The repository becomes public (GitHub's native secret scanning and dependency review become free), or the team moves to a GitHub plan that includes them.
